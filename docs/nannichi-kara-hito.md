# 人ごとの歩合・最低保証・役割を「何日から」で持つ（設計 v12・2026-10-18・速い版）

司さん 10-18「時間かかり過ぎや」：v11（docs/nannichi-kara-sekkei.md）の7段（古い画面を止める門・7日の影・全部の鍵の 2000 行）はやめ、
★人ごとの欄から1件ずつ★出す。決め（司さん 10-17）はそのまま：
- 変える日は使う人が自由に選ぶ（既定は今日・過去も先も）。その日から次の変更の日までその値。その日より前は前の値。
- 過去の日を選んだら、その日から後は遡って新しい額（本人の明細・締めて払った期も）。止めない・警告で縛らない。
- 記録の日付も値も後から直せて消せる。今いる人も辞めた人も同じ。

## 形（列＝最初の値・記録＝その日からの値）
- 表 `daikome.dk_hito_rireki`（id, company_id, employee_id, key ∈ {pay_rate, pay_floor, role}, from_date date, value jsonb, created_at）。
  unique (employee_id, key, from_date)。RLS は dk_employees と同じ（会社の持ち主だけ 読む・足す・直す・消す）＋ employee_id がその会社の人か。窓 public.dk_hito_rireki（security_invoker）。
- ★ある日 d の値★＝その人・その鍵で from_date ≤ d の一番新しい記録の value。★記録が無ければ列の値★（今と同じ）。
  value が JSON の null＝「空」（歩合・保証は役割どおり／役割は空）。
- ★記録が1行も無い人は、今と1円も違わない★（計算は列をそのまま使う＝作りで差0）。移りの行・trigger は作らない。
- 列は「最初の値（記録より前）」。日付を空にして保存した時だけ列に書く。

## 計算（js/payroll-daily.js）
- buildCtx が raw.rireki を受け、`empOn(ctx, empId, date)` が上の決まりで人の欄を組む。
  日ごとに人を引く所＝dayInput（乗った人の役・人の行の rate・floor・role）と yakuDameWoKazoeru（役割が決まりに在るか）を全部これに替える。
- raw.rireki が null・配列でない（読めなかった）＝止める（yakuDame に wake 'rireki'・明細・紙・月次を止めて訳を出す）。
  undefined は「記録を渡さない古い呼び方」＝記録無しとして扱う。★製品の buildCtx の呼び口（kyuryo 2か所・shukei 2か所）が全部 rireki を渡す事を試験で縛る★。
- 本人の画面：dk_kyuryo_get が本人の記録（rireki）と、相方の役をその日の記録で引いた crew を返す。返りに rireki が無い（古い関数）＝止める。

## 確かめ
- 単体：記録無しで今と同じ額（2通り：記録 [] と undefined）／過去の日で遡る／先の日は今日に効かない／次の変更まで効く／null で役割どおりに戻る／役割の記録で決まりに無い役＝止める／読めない＝止める。

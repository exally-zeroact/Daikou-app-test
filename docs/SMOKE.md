# ダイコメ リリース前 / タスクキル後 実機 SMOKE チェックリスト

このドキュメントは静的解析 (ESLint / Prettier / Stylelint) と
ユニットテスト (Vitest) では検出できない実機固有の挙動を
人手で確認するためのチェックリスト。リリース前 / 重大変更後 /
タスクキル復元周りに変更を加えた時は必ず通すこと。

絶対ルール:
- 距離計算は道路ジオメトリで・GPS 直線禁止
- 業務継続最優先・どんな場面でもメーター止めない
- iOS / Android 両 OS で確認 (省略不可)

---

## 1. クリーンインストール起動

### 1-1. iOS Safari → ホーム画面追加
- [ ] Safari で test URL (Vercel preview) を開く
- [ ] 共有ボタン → ホーム画面に追加 → 「追加」
- [ ] ホーム画面のアイコンから起動
- [ ] `navigator.standalone === true` であることを Eruda で確認

### 1-2. Android Chrome → ホーム画面追加
- [ ] Chrome で URL を開く
- [ ] メニュー「アプリをインストール」を選択
- [ ] アプリアイコンから起動
- [ ] `matchMedia('(display-mode: standalone)').matches === true` を確認

---

## 2. 初回起動時の許可フロー

### 2-1. iOS PWA
- [ ] 起動時に **「センサーを許可する」青ボタン** が表示される (オレンジバナーではない)
- [ ] 業務開始ボタンは表示されない (許可前)
- [ ] 青ボタンをタップ → DeviceOrientation 許可ダイアログ → 「許可」
- [ ] 続いて DeviceMotion 許可ダイアログ → 「許可」
- [ ] 続いて geolocation 許可ダイアログ → 「許可」
- [ ] 青ボタンが消え業務開始ボタンが現れる
- [ ] GPS badge が「GPS待機」→「精度Xm」に変わる

### 2-2. Android Chrome
- [ ] Android は DeviceMotion / DeviceOrientation 自動許可
- [ ] 青ボタンタップ後 geolocation 許可のみダイアログが出る
- [ ] 許可後 GPS badge が「精度Xm」になる

---

## 3. 業務開始 → 代行 → 確定 → 空車フロー

各 trip で必ず以下を確認:

- [ ] 業務開始ボタン押下 → 業務画面 (空車画面) に遷移
- [ ] 業務画面の本日売上 / 走行回数 / 実車距離 / 総走行距離 が全て **0** にリセットされる
- [ ] 「代行開始」(btnMain) 押下 → 代行中画面
- [ ] 実車中・走行距離 (driveDist) がリアルタイム加算される (= GPS が動いている)
- [ ] 「確定」押下 → 料金画面・total fare 表示
- [ ] 「空車」押下 → 業務画面に戻る
- [ ] **本日売上 = 確定 fare 合計 (¥)** が即時反映
- [ ] **走行回数 = 実車回数 + 1** に増加
- [ ] **実車総距離** が当該 trip 分加算
- [ ] **総走行距離** が業務開始からの GPS 移動全部 (実車 + 空車) を表示

---

## 4. タスクキル → 再起動 (MA の核心確認)

### 4-1. 実車中のタスクキル復元
- [ ] 代行中 (driving 画面) でアプリスイッチャから kill
- [ ] アイコンから再起動
- [ ] **実車画面が自動復元** される (centered overlay でも screenIdle でもない)
- [ ] **GPS badge が自動で「GPS待機」→「精度Xm」に変わる**
      (司さん 2026-05-14 21:46 報告事象の回帰防止)
- [ ] dlog で `[復元] 自動 startGPS` が出ている (Eruda 確認)
- [ ] オレンジバナー「センサーを再起動する」が表示される
- [ ] バナータップ → DeviceOrientation / DeviceMotion 許可ダイアログ → 「許可」
- [ ] バナー消失・走行距離 (driveDist) が再加算開始する

### 4-2. 空車中のタスクキル復元
- [ ] 空車画面 (screenIdle) でアプリスイッチャから kill → 再起動
- [ ] 業務画面が復元され、本日売上 / 走行回数 / 実車距離 / 総走行距離が正しく保存値で表示
- [ ] **「総走行距離が 0 に戻った」事象が出ないことを確認**

### 4-3. 業務終了後のタスクキル復元 (limbo)
- [ ] 業務終了ボタン押下 → 業務報告画面 (ended=true)
- [ ] アプリスイッチャから kill → 再起動
- [ ] 業務開始ページに遷移し、**業務再開ボタン** が表示される
- [ ] 業務再開ボタン押下 → 前業務の数値 (本日売上 / 走行回数 / 実車距離 / 総走行距離) が引き継がれる

---

## 5. 許可ページ → 業務開始ページ 2 段階動線

### 5-1. 真のコールドスタート (タスクキル後)
- [ ] アプリ起動直後・**1 ページ目: 許可ページ** (青ボタンのみ)
- [ ] 青ボタンタップ後・**2 ページ目: 業務開始ページ** (業務開始ボタン + 業務再開ボタン)
- [ ] 業務再開ボタンは limbo 状態のときのみ表示

### 5-2. 同 session 内のオーバーレイ往復
- [ ] 業務開始後・bottom-nav 設定タップ → 設定 overlay 表示 (page reload なし)
- [ ] GPS badge が「精度Xm」のまま維持される
- [ ] 設定 overlay 閉じる → オレンジバナー誤表示なし (司さん 2026-05-14 修正済確認)

## 6. MA-6 (bottom-nav SPA 化) 後の継続性確認

業務中に全タブ切替で以下を確認:

- [ ] 業務 / 履歴 / 使い方 / 設定 タブを順番にタップ
- [ ] **page reload が一度も発生しない** (URL bar 不変・タブの spinner 出ない)
- [ ] **GPS badge が常に「精度Xm」維持** (= MA-6 の核心目標達成)
- [ ] **走行距離 (driveDist) が overlay 表示中も増え続ける**
- [ ] overlay 閉じた直後の業務画面で連続的に距離が増加していることを確認
- [ ] MM Worker B が再起動しない (Eruda で mmStatsBadge 確認)

## 7. 履歴 overlay (MA-5)

- [ ] 実車を 1 回以上完了させる

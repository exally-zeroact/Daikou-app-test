# 役割の決まり（歩合・最低保証）を「何日から」で変える（設計 v2・2026-10-18）

司さんの決め（10-17・人の何日からと同じ）：
- 変える日は使う人が選ぶ（既定は今日・過去も先も）。その日から次の変更の日までその値。その日より前は前の値。
- 過去の日を選んだら、その日から後は遡って新しい額（本人の明細・締めて払った期も）。止めない・警告で縛らない。

## 範囲
- 給料の設定の「役割ごとの決まり」の **歩合（rate）と最低保証（floor）** だけ。
- 日給・段階歩合（pay_extra.roles）・積立・回数・距離・売上から引く物・締め日はこの件では変えない（次の件）。

## 置き場＝新しい表 dk_yaku_rireki（v1 の roles の中に置く形は捨てた）
- v1 は roles[名前].rireki に置いた。対立役 1回目 止1：事務所の画面は SW を使わず、古い版は「開いたままのタブ」で上限が無い。古い版が保存すると roles を {rate,floor} に作り直して記録が全部消える（node で確かめた）。pay_extra も同じ（hokaYomu が作り直す）。
- 別の表なら、古い版は表を知らない＝列だけを書く＝記録は消えない。列は「最初の記録より前の日」の値なので、古い版の保存は今と同じ意味。
- 表：`daikome.dk_yaku_rireki (rireki_id uuid pk, company_id fk cascade, yaku text not null, key in ('rate','floor'), from_date date, value numeric not null, created_at, unique (company_id, yaku, key, from_date) deferrable initially immediate)`。
  - date 型と unique で、ありえない日（2026-02-30）と同じ日の2件を倉庫が断る（1回目 直2）。
  - deferrable＝名前の入れ替え（甲↔乙）を1つの文で直す時に途中でぶつからない。
- 守り：持ち主だけ読む・書く・消す（4つの policy）・authenticated だけ・窓は security_invoker。
- 役割の名前を直す倉庫の関数（dk_yaku_namae_naoshi）に、記録の yaku の付け替えを同じ取引で足す。
- 本人の明細の関数（dk_kyuryo_get）に 'yakuRireki'（その会社の記録）を足す。
- ★本番の倉庫を3つ変える（表・名前直しの関数・本人の明細の関数）＝本番へ当てる前に司さんに許しを訊く★。

## 計算
- buildCtx が raw.yakuRireki を受ける。undefined＝記録無し（今と同じ）。null・配列でない・行の形が違う（yaku が字でない・key が2つ以外・日付の形・value が数でない）＝止める（yakuDame wake 'yakuRireki'）。
- `settingsOn(ctx, 日)`：各役割の各 key について from_date ≤ 日 で一番新しい記録の値、無ければ列の値。記録が無い会社は ctx.settings をそのまま返す（今と1円も違わない）。決まり（列）に無い役割の記録は使わない。
- お金で roles を読むのは計算の本体の2か所（daiko-payroll.js の役割の引きと回数・距離の比）だけで、どちらも computeDay の settings から来る（1回目 直7）＝computeDay の `Payroll.compute(inp, settingsOn(ctx, 日))` だけ替える。
- 止める訳の字 yakuDameBun に 'yakuRireki' を足す（1回目 直1）。

## 画面（給料の設定）
- 役割の行に「何日から」（既定は今日＝kyouJst・空＝最初から）と「記録 N」。
- 欄には **選んだ日に効く値** を出す（1回目 止2）。日付を変えたら出し直す。従業員の画面の薄い字（_roleRateOf / _roleFloorOf）は今日に効く値。
- 歩合・最低保証を直した時：
  - 日付が在る＝その場で記録を書く（同じ日の記録が在れば PATCH・無ければ POST）。列は変えない。保存ボタンは要らない（人の記録と同じ）。
  - 日付が空＝今と同じ（列を直して「保存する」）。
  - まだ保存していない役割（足したばかり・名前を直した後）は記録を書かせない（「先に保存してください」）。
- 段階歩合の在る役割には「売上が段の日は段の率が勝ちます」と出す（1回目 直4）。
- 記録の在る役割で日付を空にした時は「空は 最初の 記録より 前の 日だけ 変わります」と出す（1回目 直5）。
- 「記録」を押すと日付順に並び、日付・値を直す・消すができる（その場で倉庫へ）。
- 記録の在る役割は消させない（「先に記録を消してください」）。
- 記録を読めなかった時は、記録を書かせない・名前を直させない（人の記録と同じ）。

## 守る試験
- 単体：記録が無いと今と同じ額（undefined と []）／記録の日から後だけ新しい率／次の記録まで効く／先の日は今日に効かない／形が違う＝止める／本人の画面（crew）でも同じ額／止める訳の字が 'yakuRireki' を知っている／呼び口が全部 yakuRireki を渡す／読みが limit>1000。
- 画面：日付在りで直すと dk_yaku_rireki へ書き dk_payroll_settings は書かない／日付空で列（保存）／欄が打った値のまま／読めない＝止める。
- 倉庫（rollback）：持ち主だけ・よその会社は書けない・同じ日2件を断る・名前の入れ替えで記録も入れ替わる・本人の関数が会社の記録を返す。

## 覚え（前から在る・この件で変えない）
- 保存の確かめと書き込みが別の通信（窓は小さい）。
- 列の値の範囲は見ていない（35 と打てば 35倍）。前からの事。
- 遡った時に本人へ知らせは出ない（司さんの決め＝止めない・警告で縛らない）。
- seed-test-fake.sql は roles を流し直す（記録の表は触らない）。

## 対立役 2回目の指摘と答え（10-18）
- 止1（消した役割の記録が同じ名前で生き返る）→ 決まり（列）に無い役割の記録が残っていたら **止める**（wake 'yakuNokori'・訳の字に役割の名前と直し方）。設定の画面に残った記録を出して消せる。「役割を足す」は残った記録の在る名前を使わない。名前を直す時も残った記録の名前にはさせない（画面）。倉庫の名前直しは訳 'kiroku_nokori' で断る（直5）。
- 止2（空・全角が 0 で入る）→ 記録の値は半角の数で 0 以上だけ（空・全角・負は書かずに字を出す）。値の範囲（35倍等）は列も前から見ていない＝この件では変えない。
- 直1 → 画面の試験 ⑤（欄が記録の値を出したまま積立を直して保存＝列は元のまま）。
- 直2 → 記録の数・一覧・消す判じは読み込んだ時の名前で数える。
- 直3 → 日付の欄を値の前に。書けたらその行に「◯日から保存しました」。名前を直しても選んだ日付は付いていく。
- 直4 → 従業員の画面の薄い字は、その人の選んだ日の決まり。
- 直6・覚2 → 古い版のタブは列の値で計算する（人の記録と同じ形・覚え）。本番は **倉庫を先に** 当ててから画面を出す（画面が先だと表が無く、読めない＝全部止まる側）。
- 覚3 → unique は deferrable なので on conflict は使えない（画面は PATCH と POST だけ）。入れ替えはテストの倉庫で確かめた（rollback の試験 ⑥）。

**② 保険は business.js 側に付けてある**

`business.js` が1秒ごとに `state.total_distance_m` に写して保存し、`load()` で Meter に流し戻す。

**③ その保険は3回穴が開いて3回塞いでいる**

## 2. 直す形

### 方針

**メーターが自分の数字を自分で持つ。** business.js の流し戻しに頼らない。

```
今  : メーターは記憶を持たない → business.js が横から写して保存 → 起動時に流し戻す
                                  ★この経路が切れると消える（3回切れた）★

新  : メーターが走行中に自分で書く → 起動時に自分で読む
      business.js の流し戻しは ★保険として残す★（消さない）
```

### 保存するもの（`dk_meter_snapshot`）

```json
{
  "v": 1,
  "saved_at": 1785900000000,
  "session_id": "業務開始のたびに変わる印",
  "distance_m": 5320.4,
  "fare_yen": 4500,
  "wait_sec": 120,
  "elapsed_accumulated_sec": 900,
  "business_distance_m": 5320.4,
  "running": true,
  "business_active": true,
  "billing_frozen": false
}
```

**表示用（`display_*`）は保存しない。** 実距離から作り直せるため。

### いつ書くか（★1秒ごと・指示役の判断★）

| きっかけ | 理由 |
| --- | --- |
| **1秒ごと**（走行中のみ） | 5秒だと落ちた時に最大5秒＝時速50kmで約70m消える。**それは金額**。<br>`business.js` は既に1秒で保存していて本番で問題が出ていない（`GPS_SAVE_INTERVAL_MS`）。<br>**実績のある間隔に揃える。2つの違う間隔を持たない。** |
| **画面が隠れた時**（`visibilitychange` / `pagehide`） | ★これが今回の穴★。閉じる直前に確実に書く |
| 代行開始・確定・業務開始・業務終了 | 節目は必ず残す |

**書かない時**: 走っていない（`running=false` かつ `business_active=false`）＝増えていないので書く必要がない。

**書く重さは実測して報告する。** 重くて取りこぼすなら、**間隔ではなく書き方を変える**（差分だけ書く等）。**間隔は動かさない。**

### いつ読むか（★時間で切らない・指示役の判断★）

起動時に1回だけ。

**時間で切るのをやめた理由**: 代行は夜の仕事。18時開始・翌5時終了で11時間。
**長い日は12時間を超える。一番長く働いた日に消えるのが一番まずい。**

**復元する条件**:

- 保存が `v:1` で読める
- **保存の `business_start_time` が、今の業務の `start_time` と一致する**
  → **何時間でも安全。前日の残骸も拾わない。**
- `saved_at` が**未来でない**（時計が狂った端末での事故防止）

条件を満たさなければ **復元しない（0から始める）**。
**時刻の長さでは判断しない。** 端末の時計に依存しない形にする。

### 書き方（距離の計算を邪魔しない）

- 書くのは**別のタイマー**。距離を足す処理の中では書かない
- `localStorage` が使えない端末でも**業務は止めない**（`try/catch` で握りつぶす）
- 書く量は1KB未満

## 3. 過大ゼロを守る（★不可侵★）

**復元は「増やす」方向に働きうるので、ここが一番危ない。**

| 決まり | 理由 |
| --- | --- |
| 復元は**起動直後の1回だけ** | 途中で何度も復元すると足し込まれる |
| 復元後は**必ず上書き（代入）。足し算にしない** | `+=` にすると二重になる |
| 復元値が**今の値より小さければ復元しない** | 戻す＝過小方向。安全側 |
| `saved_at` が未来ならば復元しない | 時計がずれた端末での事故防止 |
| **復元で `fare_yen` を計算し直さない** | 保存時の確定値をそのまま使う |

テストで固定する内容:

- 復元を2回呼んでも距離が2倍にならない
- 復元しても `distance_m` が保存時より**1mmも増えない**
- 壊れた保存・古い保存・未来の保存 → **復元しない**
- 保存が無い端末 → 0から始まる（今までどおり）

## 4. 「閉じる／落ちる」を通るテストを標準にする

**今までのテストは1回のページ内で完結していたので、この形を1度も見ていません。**
これが本当の原因です。以下を標準の型にします。

| 通す形 | 見ること |
| --- | --- |
| 業務開始 → 走行 → **再読込** → 業務終了 | 距離が残る |
| 業務開始 → 走行 → **12時間空ける** → 開き直す | 復元しない（別の日） |
| 業務開始 → 走行 → **3時間空ける** → 開き直す → 業務終了 | 距離が残る |
| **代行中に落ちる** → 開き直す | ★料金が残る（一番怖い）★ |
| 走行 → 閉じる → 開き直す → **もう一度閉じて開く** | 二重にならない |
| **オフラインのまま**走行 → 閉じる → 家でWi-Fi → 業務終了 | ★今回の形★ |

**先に書いて、今の状態で赤になることを実測してから直します。**

## 7. 料金の復元（★指示役の判断・2026-08-04★）

**復元する。ただし黙って戻さない。**

**復元しない＝実際に走った分を請求できない＝運転手が損をかぶる。それは安全ではない。**
「過大ゼロ」は**実際より多く取らない**という約束であって、
落ちる直前まで実際に走った分を戻すのは**過大ではない**。

危ないのは**別の代行の料金を戻すこと**。そこを2つで縛る。

### (a) 同じ代行だと確認できる時だけ戻す

保存に**代行の開始時刻（trip の識別）**を持たせ、今の代行と一致する時だけ戻す。
一致しなければ **料金も待機時間も戻さない**（距離だけ戻す）。

### (b) 戻したことを画面に出す

```
前回の続きから　1,850円 / 3.2km
```

**運転手が目で見て、違えば止められる形にする。**

`wait_sec`（待機料金）も**同じ扱い**。

**「復元しました」の表示が出ないまま金額が戻る経路は、テストで赤にする。**
